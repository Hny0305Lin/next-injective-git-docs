## 背景

不可变 EVM 套件与只读的 CosmWasm V1 归档查看器均已实现。导入全部历史
V1 仓库将需要：固定切换高度、盘点、确定性迁移计划、签名广播日志、回执
集、导入状态一致性证据，以及普通 EVM 产品中的历史别名支持。

当前产品决策是不把 CosmWasm V1 状态带入 EVM 套件。V1 仍可用于历史查阅，
但它不是活的兼容性后端，也不参与 EVM 写入。

## 决策

1. 当前 Injective EVM 测试网套件以空应用状态启动。
2. CosmWasm V1 仅通过显式的只读归档预览暴露。普通 CLI、Web 仓库与
   remote-helper 操作保持仅 EVM。
3. 当前切换不要求 V1 盘点、迁移计划、迁移 manifest、操作员演练日志、
   迁移回执日志或导入状态比对。
4. 空状态验收改为要求：哈希绑定的 `cutover-scope.json`、每个模块的零
   预期/导入计数、匹配的空滚动根、用户名托管非负债证据、激活日志，以及
   固定区块的套件激活验证。
5. 迁移操作员保留并为另行审批的未来迁移持续测试，但它不是本次全新套件
   切换的阻塞项。
6. 历史 V1 别名是归档查看器的关注点，不是普通 EVM Git 兼容性要求。

## 后果

- 历史 v3 P1.3 范围使用经过验证的零导入激活，而非 V1 数据一致性；它不
   满足后继或产品验收。
- 既有的 V1 仓库不会自动出现在 EVM 套件中；若要成为活跃 EVM 仓库，必须
   重建。
- 没有 V1 写回退、双写或隐式跨运行时读取。
- 切换门禁从显式 scope 文件中选择证据要求：本决策对应空状态证据；若未来
   获批的切换选择 `cosmwasm-v1-migration`，则对应完整迁移证据。
- 独立安全评审、干净的 Windows/Linux Git E2E、Web 钱包回执、最终性文档
   与哈希绑定审批仍然强制。

## 验收

固定区块的套件证据必须显示：版本 3、激活状态、七个已终结模块、零预期与
零导入记录、零批次与序列、预期/滚动根匹配、运行时代码哈希验证、不可变的
Directory 绑定。V1 归档面必须保持只读，并与普通 EVM 产品路径分离。
